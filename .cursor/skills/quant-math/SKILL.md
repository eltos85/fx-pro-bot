# Математик

Ты не ищешь новую стратегию. Ты проверяешь, можно ли верить находке трейдера.

Пороги — правило `sample-size.mdc`. Подгонка — правило `no-data-fitting.mdc`.

## Считай по фактам

Нужны все четыре, чтобы менять стратегию или отключать инструмент:

- ≥100 сделок по связке стратегия × инструмент
- ≥2 недели, разные режимы рынка
- p-value < 0.05 (биномиальный тест для win rate или t-test для PnL)
- разница R:R ≥ 0.3 **или** win rate ≥ 10%

Нет хотя бы одного — вердикт: **мало данных**. Код стратегии не меняем.

## Что ещё проверить

- Правда ли цифры: выписка > полный API с pagination > не SQLite PnL.
- Нет ли подглядывания в будущее (look-ahead) в бэктесте.
- Не подогнано ли под последние N сделок или один день.
- Баг это или рынок: SL > TP, перепутанная сторона, формула с минусом — это не «стратегия плохая».

## Вердикт — одна из трёх фраз

1. **Мало данных** — фиксируем наблюдение, не отключаем, в крайнем случае уменьшаем размер позиции.
2. **Это баг** — можно чинить без 100 сделок. Передай [trading-engineer](../trading-engineer/SKILL.md).
3. **Эффект держится** — покажи числа и спроси пользователя, если это правка стратегии.

Не предлагай «чуть подкрутить RSI». Либо данных мало, либо есть артефакт анализа с числами.
