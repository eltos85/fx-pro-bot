# Противоречия в логике scalp_bot — реестр для разбора

Назначение: фиксировать **внутренние противоречия** между значениями/формулами/
философиями стратегий (источник — `STRATEGY_RATIONALE_SCALP.md`) и **накапливать
по ним исследования**, пока не придём к решению. Это рабочий документ: добавляем
противоречия и складываем сюда research/A-B, на основании которых принимаем
вердикт.

## Как пользоваться

- Каждое противоречие — отдельная запись с ID (`C-NN`).
- Статусы: `🔴 открыто` → `🟡 в работе (копим research)` → `🟢 решено` →
  `⚪ принято как by-design` (намеренное, не баг).
- В «Исследования» складываем ссылки на канон, артефакты `data/`, A/B-логи,
  цитаты. Каждая запись с датой и тегом источника (`[research]`/`[наш A/B]`).
- Менять торговую логику по итогам — только по правилам (strategy-guard.mdc,
  sample-size.mdc, no-data-fitting.mdc): research/данные → вердикт → правка.

## C-01: ширина SL — комиссия против шума

**Статус**: 🟢 решено (v0.18.8, 2026-06-05)
**Где**: `min_risk_fee_mult = 4.0` (общий, мин-R пол) ↔
`sweep_fade_sl_risk_mult = 2.0` (sweep_fade, v0.18.8).
**Суть (была)**: мин-R пол задавал ширину SL из СТОИМОСТИ КОМИССИИ (R ≥ 4×
round-trip), а множитель раздвигал SL из ШУМА рынка (MAE). Две логики на одной
величине; вдобавок при ×mult порог flow_exit/TP уезжал вместе с раздутым стопом
(рассинхрон: лок на 1.5×mult вместо 1.5R).
**Почему важно**: дублирование/конфликт привязок; раздутый flow_exit пропускал
~16% винеров.

**Исследования**:
- [2026-06-04] [research] MAE/Sweeney 1988 — стоп по реальному ходу против входа,
  не по косту. MR: тугой стоп (1 ATR) убивает edge (aligrithm 3.27 2026).
- [2026-06-05] [наш A/B] MFE 734 sweep_fade-сделок (`data/scalp_sf_mfe_out.txt`):
  цель/лок надо мерять ходом В ПЛЮС (winner-MFE медиана 2.33R), он от ширины стопа
  не зависит → TP и flow_exit ОТВЯЗАНЫ на `base_risk`.
- [2026-06-05] [наш A/B] MAE-винеров по Sweeney (`data/scalp_sf_mae_out.txt`,
  n=412): p85=1.87R, p90=2.39R → канон-ширина ≈2.0 (×1.5 сохраняет лишь 78%
  винеров — ниже полосы; ×2.0 = p85, 85%).
- [2026-06-05] [наш A/B] decoupled harness июнь 1–4 (`data/scalp_sl_decouple_ab.txt`):
  netR ×1.0 −73R → ×1.5 −7R → ×2.0 +15R. Сходится с MAE-перцентилем.

**Вердикт**: РЕШЕНО decoupling-ом. Разделены ДВЕ независимые привязки, конфликта
больше нет: (а) **SL** = MAE/Sweeney (буфер от шума), ширина ×2.0 = p85 MAE-винеров;
(б) **TP + flow_exit** = MFE на `base_risk` (структура+комиссионный пол), от ширины
SL не зависят. Комиссионный пол остаётся первичной привязкой `base_risk` (он же
R-единица целей), MAE-множитель действует ТОЛЬКО на SL. Реализация: `build_signal`
(`base_risk` vs `sl_risk`), `SweepFadeStrategy.should_exit` (порог на `base_risk`).

## C-02: порог ADX-гейта — калибровался под узкий стоп

**Статус**: 🟢 решено частично (v0.18.9: порог 25→30 под SL ×2.0); асимметрия
MR vs momentum остаётся by-design.
**Где**: `htf_adx_max` блокирует sweep_fade/density_bounce ↔ `regime_gated=False`
у density_break ↔ новый широкий стоп `sweep_fade_sl_risk_mult=2.0`.
**Суть**: (а) одно значение силы тренда для MR = запрет, для momentum = желаемое
(by-design асимметрия). (б) САМ порог 25 был выставлен под старый узкий стоп ×1.0;
после перехода на ×2.0 фейд в умеренном тренде (ADX 25–30) выживает → порог 25
стал слишком строгим (резал прибыльные фейды).
**Почему важно**: фильтр не был синхронизирован с шириной стопа — параметр одной
правки (стоп) изменил оптимум другой (гейт).

**Исследования**:
- [2026-06-04] [research] MR: «never fade a trending market» (Connors/Raschke
  1995); сильный тренд (≥30) — особенно. Momentum хочет тренда (Quant Signals).
- [2026-06-05] [наш A/B — OOS, 2 окна при ×2.0] ADX-корзины без гейта
  (`data/scalp_adx_buckets_x2_jun.txt`/`_may.txt`): 25–30 прибыльна в ОБА окна
  (+18.3/+5.5), ≥30 нестабильна (+13.0/−18.1). При ×1.0 25–30 была непостоянна
  (+7.6/−7.8) → виноват именно узкий стоп.

- [2026-06-05] [наш A/B — density_break ADX-корзины, ЗАКРЫВАЕТ пробел]
  42 заполненных (`data/scalp_dbr_mfe_mae_adx_out.txt`): худшая корзина — чоп
  ADX<20 (WR 0%, n=9), умеренный 25–30 наименее-убыточен (WR 40%), ≥30 WR 27%.
  Net-минус во ВСЕХ (n=42 = шум). Асимметрия «momentum хочет тренда» подтверждена
  слабо-направленно (чоп <20 убивает пробой — канон), но положительного эджа нет
  ни в одной корзине → отдельный ADX-floor для density_break НЕ ставим.

**Вердикт**: порог поднят 25→30 (режем только strong ≥30, Connors/Raschke;
пропускаем 25–30, где фейд с ×2.0 выживает OOS). Асимметрия MR↔momentum (гейт
ВКЛ для фейдов, ВЫКЛ для density_break) — by-design, ПОДТВЕРЖДЕНА корзинами
(density_break хуже всего в чопе <20, не в тренде). Пробел закрыт: на n=42
положительного эджа по корзинам нет → ADX-floor для пробоя пока не вводим,
пересмотр на ≥100. density_bounce делит гейт, но на ×1.0 и n≈12 — шум, мониторить.

## C-03: выходная механика — flow_exit/scratch против голого TP/SL

**Статус**: ⚪ принято как by-design
**Где**: sweep_fade (`flow_exit`/`flow_scratch` по флипу ленты) ↔
density_break (`should_exit = None`, только биржевые TP/SL).
**Суть**: sweep_fade активно управляет выходом по ордер-флоу; density_break
ведётся голым TP=3.5R/SL. Разные философии выхода для двух страт одного бота.
**Почему важно**: by-design (Философия B для пробоя — winners run без дискреции;
flow_exit придуман под фейд). Гипотеза «снизить TP/добавить flow-выход из-за
разворотов перед TP» отвергнута каноном (v0.18.10): TP вернули на 3.5R, flow-выход
несовместим со структурным стопом — пересмотр только отдельной итерацией на ≥100.

**Исследования** (накапливаем):
- [2026-06-04] [research/no-data-fitting] flow-выход для density_break — отдельная
  итерация ПОСЛЕ валидации базового эджа (чтобы не оверфитить).
- [2026-06-04] [наш A/B] контрфактуал TP density_break: пробои разворачивались с
  2.5–3.4R до 3.5R (#973/#977/#661) → снизили TP до 2.5R (`q_db_mfe`, n=25, шум).
- [2026-06-05] [research] КЛЮЧЕВОЕ: стоп density_break **структурный** (за пробитой
  стеной = инвалидация ложного пробоя; Данилов/Bookmap liquidity-void/Brooks
  failed-breakout), а НЕ шумовой как у sweep_fade. Поэтому к нему НЕ применимы ни
  MAE-расширение SL (держали бы провалившиеся пробои), ни flow_exit на base_risk —
  это сломало бы его канон. v0.18.8 явно прибил `sl_mult=1.0` в density_break.
- [2026-06-05] [наш A/B — MAE-санити] винеры density_break до +1.5R (n=16) почти
  не уходят в минус (медиана MAE 0.32R, p90=0.77R), структурный стоп ×1.0 сохранил
  бы 100% → стоп НЕ в шуме, расширять не нужно (независимое подтверждение канона).
- [2026-06-09] [наш контрфактуал sweep_fade — `scripts/scalp_flow_exit_audit.py`]
  flow_exit ПОЛЕЗЕН, НЕ виновник R:R<1. n=52 flow_exit (чистое окно 06-05 11:00→
  06-09): снимает avg +0.89R; при удержании до родного TP/SL 65% (34) дошли бы до TP
  (украдено +28.44R, ~+0.84R/сделку), 31% (16) до SL (спасено +29.56R, ~+1.85R/сделку)
  → ЧИСТО **+1.13R** (убрать flow_exit = на 1.13R хуже). На винёрах выходит поздно
  (мелкий steal), на лузерах спасает рано/много — калибровка верная.
- [2026-06-09] [диагноз sweep_fade — `scripts/scalp_sf_diag.py`] R:R 0.79 (avgW +8.78
  vs avgL −11.14) при WR 53.7% (n=108 с 06-05 11:00) = **breakeven в пределах шума**:
  net −47.83 ≈ −4.3R ≈ **−0.04R/сделку**, PF 0.91; безубыток при R:R 0.79 = WR 55.9%
  (отставание 2.2 п.п.). Стороны сбалансированы (long 50.9% / short 56.6% — инверсии
  входа/тренда НЕТ). HTF-фильтр работает (ZEC 06-08: цена росла 431→456, фильтр пускал
  trend-aligned лонги, 0 шортов; −73.9 = 10 fade-лонгов на сверхволатильной ZEC,
  стоп тесен под её ~3-6% качели — волатильность инструмента, не логика). Вывод:
  эдж входа/тренда НЕ сломан; страта у безубытка. Рычаг (если будет) — дать винёрам
  бежать дальше (частичный scale-out / профит-лесенка), ТОЛЬКО после контрфактуала
  «steal vs save по R-бакетам» + OOS + одобрение. Тюнить flow_exit рефлекторно ЗАПРЕЩЕНО
  (no-data-fitting): на n=108 у безубытка изменение порога = подгонка под шум.
- [2026-06-09] [research-КАНОН — выходная механика MR-фейда, СНИМАЕТ гипотезу «дать
  винёрам бежать»] профи единогласно: для mean-reversion полный выход по разрешению
  сигнала каноничен, scale-out/трейлинг ВРЕДЯТ. (a) traderssecondbrain «Take Profit
  Methods»: «Mean-reversion/range fade → FULL EXIT. Edge concentrates at reversal point.
  Trailing past target loses edge»; scale-out на MR деградирует 10-25%, трейлинг 20-40%;
  «High-WR scalping 60-70% WR, 1:1–1.5:1 R:R — edge comes from win rate, not outsized
  winners». (b) Connors/Raschke «Street Smarts»: MR-сетапы 55-65% WR, R:R 1:1–1:1.5,
  «main goal: minimize risk, not maximize profit». (c) Kalena DOM + BIS: удержание дольше
  окна разрешения сигнала резко роняет profitability коротких страт. → R:R 0.79 = НОРМА
  MR (чуть ниже пола 1:1), flow_exit КАНОНИЧЕН; рычаг лифта R:R — НЕ крупнее винёры
  (это сломало бы эдж), а сторона ЛУЗОВ/WR.
- [2026-06-09] [research-КАНОН — сторона лузов] Connors RSI2 (QuantifiedStrategies):
  «fixed stop-losses often reduced performance for this reversion strategy, as they
  frequently exited prematurely before the expected bounce materialized» → структурный
  −1R на гипер-вол альтах (ZEC 06-08) = именно premature-stop. Канон-выход MR = TIME-stop
  («exit after 5-10 bars if no reversion») + индикатор-кросс, а не тесный фикс-стоп.
  Carmine (order-flow): «when ranges expand, give price room while keeping same dollar
  risk» → стоп-ДИСТАНЦИЯ под волатильность инструмента. КАНОН-кандидаты лифта R:R (НЕ
  трогая flow_exit, только после loser-anatomy замера + OOS + одобрение): (1) time-scratch
  незавернувших сделок у безубытка вместо досиживания −1R; (2) vol-aware стоп-дистанция
  на гипер-вол альтах. ОБА требуют loser-anatomy анализа перед любым кодом (n=108 у
  безубытка — sample-size).
- [2026-06-09] [→ вынесено в C-07] детальная WR-декомпозиция по инструментам (вся
  просадка = ZEC, ex-ZEC WR 58.7%/+43.71), отвергнутый vol-ceiling и блэклист-канон —
  это подбор/пригодность инструментов, не выходная механика → перенесено в C-07.

**Вердикт**: by-design, УСИЛЕНО каноном И замером — разные природы стопа
(структурный vs шумовой) делают разные выходные механики правильными, а не
случайными; MAE-санити подтвердил, что структурный стоп ×1.0 не в шуме.
flow-выход для density_break пересмотреть на ≥100 сделок ОТДЕЛЬНО (не копировать
sweep_fade).

## C-04: SL-cooldown после стопа — окно по стратегии

**Статус**: ⚪ принято как by-design (v0.18.14, 2026-06-08)
**Где**: `sweep_fade_sl_cooldown_sec = 3600` (60м, fade) ↔ `sl_cooldown_sec = 300`
(5м, density_break/bounce). Диспетчер — `ScalpSettings.sl_cooldown_for(strategy)`.
**Суть**: одно и то же правило «не перефейдить провалившийся уровень сразу» имеет
РАЗНОЕ окно по стратегии — fade ждёт 60м, пробой/бонс 5м. Тот же класс асимметрии,
что C-02 (ADX-гейт) и C-03 (выходная механика): один концепт, разные значения
per-strategy под разную природу страты.
**Почему важно**: окно, валидированное для fade на длинной истории, нельзя слепо
тащить на density_break (пробой — момент; длинная пауза backwards режет повторный
импульс) и density_bounce (мало сделок, длинное окно не валидировано).

**Исследования**:
- [2026-06-08] [наш sweep] `scripts/scalp_cooldown_sweep.py` на истории sweep_fade
  (n=829): Δnet vs выкл монотонно 5м +3.53 → 30м +68.59 → **60м +103.77** → 90м
  +109.61 (колено на 60м, дальше прирост резко гаснет). Чистое окно n=93: пик на
  60м (+40.01), 90м падает. Текущие 5м для fade почти бесполезны (в чистом окне
  ровно 0 — серийные перефейды шли через 8–82 мин, кулдаун 300с не ловил ни одного).
- [2026-06-08] [research] канон MR-фейда сходится на ≥60м: Fondeo (VWAP MR) «if
  stopped — done ≥60 min»; quantfoundrylab kill-switch «2 SL → 45-min halt»;
  Connors/Raschke «Street Smarts».
- [2026-06-08] [наблюдение live — направление по факту рынка] ZECUSDT long SL
  11:47 UTC → весь час окна цена шла вниз (дно −4.4%); перефейд лонга словил бы
  серию SL. NEARUSDT (density, окно 5м) — падение было коротким, 300с хватило, и
  настоящий отскок пришёл сразу за окном. Оба кейса подтверждают разделение окон.
- [прагматика — синхронизация с ротацией/сайзингом] кулдаун DB-backed
  (`db.last_sl_close_ts` по symbol+side из таблицы `trades`), НЕ зависит от
  членства в авто-вселенной. Монета, выпавшая из топа после SL и вернувшаяся в
  течение окна, остаётся под блоком → 5-мин ротация (`_rotate_universe`) кулдаун
  не сбрасывает. На формулу лота и отбор монет кулдаун не влияет (только гейт входа).

**Вердикт**: by-design. sweep_fade=60м обоснован sweep n=829 (>порог sample-size
100) + каноном MR; density_break/bounce остаются на 300с (пробою длинная пауза
backwards; bounce — n мал, длинное окно НЕ валидировано → мониторить, при наборе
сделок проверить отдельно). Конфликта с подбором монет и риск-сайзингом нет:
кулдаун персистентен (DB по symbol+side), на универсум/лот не влияет.

## C-05: вселенная под волатильность ↔ density_bounce: near_round-гейт (РЕШЕНО v0.18.15)

**Статус**: 🟢 решено каноном + замером (v0.18.15, 2026-06-08); edge на форвард-тесте (n=12)
**Где**: авто-отбор `data/universe.py` (range 6–20% + RVOL + turnover + spread) ↔
эдж `density_bounce` (стена ≥`density_wall_mult`×baseline у круглого числа, persist).
**Суть**: вселенная ранжирует по ВОЛАТИЛЬНОСТИ/обороту/спреду (правильное сырьё для
sweep_fade), а density_bounce зависит от ДРУГОГО измерения — устойчивой ГЛУБИНЫ
стакана (resting walls). Range-floor 6% к тому же ВЫКИДЫВАЕТ самые глубокие мейджоры
(BTC/ETH/SOL/XRP, range 2.5–5.4% — `universe.py` docstring), где стены у круглых
уровней наиболее надёжны. Волатильные альты в топе чаще имеют тонкие быстрые книги
(стену съедают/спуфинг). → density_bounce структурно голодает на вселенной,
заточенной под собрата-фейда.
**Почему важно**: объясняет хронический near-zero объём density_bounce (n≈12 за всю
историю) НЕ только «стена редка», а несоответствием критерия отбора монет природе
страты. Пока n<100 — эджи density_bounce в принципе не накопить (sample-size).

**Исследования** (накапливаем):
- [2026-06-08] [наблюдение кода] `universe.py` docstring: range-floor 6% режет
  BTC/ETH/SOL/XRP (2.5–5.4%) — самые глубокие книги. Отбор не содержит метрики
  глубины/walls вообще (turnover = оборот, не depth; spread ≤5bps = top-of-book,
  не объём за уровнями).
- [2026-06-08] [замер из RATIONALE] density_bounce ~12 заполненных за историю, все
  вышли по `density_gone`; остальное entry_Cancelled/timeout. n=12 ≪ 100 = шум.
- [2026-06-08] [взаимодействие с сайзингом] комиссионный пол `min_risk_fee_mult=4`
  (R≥0.30% цены, `build_signal`) отодвигает SL ЗА стену, если структурный стоп ближе
  пола → «короткий стоп за стеной = хороший R:R» (Данилов) эрозит именно на
  отобранных монетах. `sl_mult=1.0` (без MAE-расширения) это не компенсирует.
- [2026-06-08] [наш замер 1 — `scripts/scalp_density_universe_audit.py`,
  `data/scalp_density_universe_audit.txt`] гипотеза «мейджоры wall-rich, вселенная
  голодает» НЕ подтвердилась: wall_rate (стена ≥5×base ∧ near_round 0.3%) vol-
  вселенная 0.00 (0/5), исключённые мейджоры 0.02 (BNB 1 раз). НО `concentr`
  (max-уровень/base) высокий у многих (BTC 51×, ETH 10×, NEAR 5.8×) — стены ЕСТЬ,
  их режет near_round. Высокий wall_rate только у памп-альтов (range 47–54%), что
  range-cap 20% исключает. [ограничение] 1 прогон ~13:51 UTC.

## C-08: density_break без трендового фильтра — контртренд-ЛОНГ-пробои = bull traps

**Статус**: 🟡 решено-частично (v0.18.18: асимметричный DMI long-gate включён,

  p<0.02 → статистически значимая поломка, НЕ шум (в отличие от ZEC C-07 n=16).

  (fill-rate 43.9%→100%) и single-bar фейк, но WR застрял 20.8%→20% — правка
  била не по причине. Причина — НАПРАВЛЕНИЕ: пробой в контртренд.

**Исследования (канон)**:
- [2026-06-10] [research] «Breakouts against the dominant trend carry a
  significantly higher probability of bull/bear traps; counter-trend breakouts
  have much higher failure rate — take only with extra confirmation/smaller
  size» — 5 независимых источников: NYC Servers breakout guide, ToS Indicators
  false-breakout checklist, PhotonTrading MTF, FMZQuant breakout-retest (200
  EMA trend-align), Kaufman «Smarter Trading» 1995 (ER: choppy → fakeouts).
- [2026-06-10] [research-КОНФЛИКТ и примирение] docstring v0.18.1 цитирует Quant
  Signals (175 backtests): СИММЕТРИЧНЫЙ трендовый фильтр на пробое = «universal

  симметричный фильтр; наша поломка — односторонняя (лонги ≫ хуже шортов, тот же

  лонг-стороне, Kalena 2026).

на density_break — ровно тот, что валидирован на sweep_fade (v0.18.4, A/B 3 окна):
лонг-пробой разрешён только при +DI>−DI; шорты свободны. Симметричный
EMA/ADX-фильтр НЕ ставим (`htf_filtered`/`regime_gated` остаются False) →
запрет Quant Signals не нарушен, profitable контртренд-шорты сохранены.
Реализация: класс-флаг `di_long_gated=True`; селектор `di_long_strats` в
`main.py` (`di_long_gated` с фолбэком на `htf_filtered` — MR-страты наследуют);
тест `test_di_long_gate_covers_density_break`. Реверсивно (`htf_di_long_gate`).
[ОГРАНИЧЕНИЕ] live-выборка одного макрорежима (даунтренд альтов); гейт
динамический — в аптренде DMI сам разрешит лонги. Пересмотр при n≥50 лонг-
сигналов в аптренд-режиме. Связь: C-06 (universe для density_break ок),
C-07 (та же асимметрия лонгов, инструментный уровень).
